# 방어적 패턴

[English](README.md) | [中文](README.zh.md) | 한국어

어렵게 얻은 규칙들: 이 디렉터리의 각 패턴은 이 저장소가 리뷰에서 강제하는 요구 사항이며, 규칙과 그 규칙이 막는 결함의 형태로 제시됩니다. 모든 규칙은 지켜야 할 조건, 리뷰어가 판단하는 기준, 경계와 예외 승인자, 올바른 예와 잘못된 예를 함께 밝힙니다. 변경하려는 산출물에 해당하는 페이지를 변경 전에 읽으세요.

## 이런 규칙이 필요한 이유

다음 다섯 가지 습관이 이후 내용의 대부분을 포괄하며, 각 페이지는 이 습관을 특정 산출물에 적용한 것입니다:

- **정확성을 명시적으로 만드세요.** 이름 있는 호출 지점, 명시적인 수명 주기, 명시적인 조건과 타입처럼 구조에 적어 넣고, 나중에 타이밍으로 보정하지 마세요.
- **단일 진실 공급원을 유지하세요.** 데이터 하나에는 읽기 경로 하나, 사실 하나에는 자리 하나, 공유 상태에는 소유자 하나를 둡니다.
- **등록된 seam을 통해 확장하세요.** 새 기능은 등록하고, 기존 캐리어(carrier)는 내부에 분기를 늘리는 대신 새 로직을 받지 않습니다.
- **변경 범위와 검토 범위를 일치시키세요.** 변경은 명시한 동작 변경에 필요한 줄만 담고, 마이그레이션은 코드를 다시 쓰지 않고 옮기며, 성능에 민감한 변경은 측정값을 함께 담습니다.
- **증거를 요구하세요.** 주장은 손으로 동기화하지 않고 변경 전후를 측정하거나 게이트로 검사하는 방식으로, 반증 가능하고 다시 계산할 수 있어야 합니다.

|---|---|
| 패키지 export, 패키지 구성, 빌드 면(face), 의존성 선언 | [package-surface.md](package-surface.ko.md) |
| 원격 서비스, `@Remote` 메서드, API 디스패치, API 계층의 업무 소유권 | [remote-and-api.md](remote-and-api.ko.md) |
| 클라이언트 컴포넌트, 슬롯, 스토어, 훅, 효과 | [client-components.md](client-components.ko.md) |
| 세션 읽기, 보유(retention), 대화 노드, 렌더러 | [conversation-and-session.ko.md](conversation-and-session.ko.md) |
| 타이밍, 상태 표현, 공유 소유권, 탈중앙화, 리팩터링, 마이그레이션, 성능 증거, 디스포즈(dispose), 콜백, 하위 프로세스 | [general.ko.md](general.ko.md) |

타입 정의와 하위 시스템별 시맨틱은 [subsystems/](../subsystems/README.ko.md)에 있습니다. 이 디렉터리는 규칙을 담고, 시맨틱 페이지는 각 타입이 무엇을 뜻하는지 담습니다. [dsh-code-review](../../.agents/skills/dsh-code-review/SKILL.md)는 풀 리퀘스트를 판단할 때 이 디렉터리를 읽으며, 개발 절차도 [AGENTS.md](../../AGENTS.md)에서 같은 표를 거칩니다.
