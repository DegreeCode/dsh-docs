# DSH 통합 모서리 반경 표준

[English](ui-radius.md) | [中文](ui-radius.zh.md) | 한국어

## 요약

컴포넌트의 역할과 크기에 따라 일관된 모서리 반경을 선택하고, 중첩 영역, hover 채움, 배경, 획을 정렬합니다. 이 표준은 DSH Web과 Desktop의 버튼, 셀, 카드, 메뉴, 대화 상자, 아바타를 다룹니다.

<a id="scope"></a>
## 범위와 권한

이 참조는 DSH Web과 Desktop의 반경 스케일과 그 컴포넌트 규칙을 정의합니다. 국소적 시각 조정은 이름이 지정된 컴포넌트나 계열로 범위가 한정되며 전역 스케일을 자동으로 바꾸지 않습니다.

[Web UI 스타일 참조](web-styling.ko.md)가 일반 스타일링 소유권을 정의합니다. 공유 값은 [`base.css`](../packages/client/ui-theme/src/styles/base.css)에 있고, 곡선 동작은 [`corner-shape.css`](../packages/client/ui-theme/src/styles/corner-shape.css)에 있습니다. 규칙을 바꿀 때는 테마 구현과 이 표준의 두 언어 버전을 함께 갱신하세요.

<a id="radius-scale"></a>
## 반경 선택

H는 테두리를 포함한 CSS 픽셀 단위의 설계된 외곽 높이입니다. R은 브라우저가 겹치는 모서리를 제한하기 전의 CSS `border-radius`입니다. 먼저 컴포넌트 역할을 고르고, 그다음 크기 변형을 고르세요. 너비, 레이블 길이, 우발적 줄바꿈, 콘텐츠 확장은 더 큰 반경을 독립적으로 선택하지 않습니다.

| 역할 | 일반 치수 또는 예 | 반경 | 공유 토큰 |
|---|---|---|---|
| 작은 디테일 | H20 미만; 키캡, 인라인 코드, 아주 작은 컨트롤 | R4 | `--dsw-radius-xs` |
| 컴팩트 컨트롤 | H20–28; 작은 버튼, 컴팩트 아이콘 버튼, 컴팩트 메뉴 항목 | R8 | `--dsw-radius-sm` |
| 표준 컨트롤 또는 단일 행 셀 | H32–40; 버튼, 입력, 선택기, 탐색 행 | R12 | `--dsw-radius-md` |
| 큰 컨트롤 또는 그룹 콘텐츠 | 큰 버튼, 의도적으로 여러 줄인 셀, 중첩 폼 그룹 | R16 | `--dsw-radius-lg` |
| 독립 콘텐츠 카드 | 설정 카드, 메시지 말풍선, 가이드 진입 카드 | R20 | `--dsw-radius-xl` |
| 기본 둘러싸는 표면 | 작성기, 대화 상자, 기본 또는 플로팅 패널 | R28 | `--dsw-radius-panel` |

제안된 컨트롤이 이 구간 사이에 있으면 기존 공유 크기 변형을 선호하세요. 더 높은 카드는 여전히 카드입니다. 버튼 높이를 넘는다는 이유만으로 R28로 승격하지 마세요. 의도적으로 여러 줄을 위해 설계된 여러 줄 셀은 R16을 사용하고, 레이블이 줄바꿈되는 일반 버튼은 버튼 변형을 유지합니다.

구체적 기본값: `Button`은 `sm`에 H28/R8, `md`에 H36/R12를 사용하며 outline 변형도 포함합니다. 표준 H32 입력과 H36 선택기는 R12를 사용합니다. Workspace 파일과 New terminal 가이드 항목은 제목만 있는 변형과 설명이 있는 변형 모두 R20을 사용합니다. R28은 그 항목이 아니라 이를 둘러싼 패널이나 대화 상자에 남겨 두세요. Composer 통계와 컨텍스트 점유 트리거는 hover, 확장, 포커스 상태를 포함해 테마 곡선의 컴팩트 컨트롤 R8을 사용합니다.

코드 블록, diff, 미리 보기 카드는 R16을 공유합니다: 변경된 파일 진입 카드, 전달된 파일 카드, 제출된 계획 카드, 생성된 작업 카드, 전송 전후의 일반 파일 첨부 카드, hover 미리 보기 패널. 변경된 파일, 전달, 제출된 계획, 생성된 작업 카드 안의 40px 아이콘 타일은 컴포넌트별 예외로 네 모서리 모두 R10을 사용하며 두 테마에서 같은 중립 타일 채움과 테두리를 공유합니다. 그 hover 채움은 같은 윤곽을 유지합니다.

<a id="shapes"></a>
## 토큰 재사용과 의도된 형태 보존

기능 소유 기하를 추가하기 전에 `ui-primitives` 컨트롤을 재사용하세요. 고정 외곽 치수에는 `box-sizing: border-box`를 사용합니다. 채움, outline, ghost, 로딩, 비활성 변형은 같은 크기와 반경을 유지하며, hover, 눌림, 선택, 포커스 상태는 반경을 바꾸지 않습니다.

일반 컨트롤과 카드에 10px, 14px, 18px, 24px 같은 로컬 값을 도입하지 말고 이름 있는 토큰을 소비하세요. 일정 컨트롤, Desktop 온보딩, 계정 알림, 단축키 컨트롤은 패키지 소유 기하를 유지합니다. [반경 예외 기록](../packages/client/ui-theme/tests/expected/radius-exceptions.expected.json)은 패키지 전체를 예외로 두지 않고 허용되는 파일, 선택자, 선언을 각각 고정합니다. `--dsl-guide-entry-radius`처럼 계열별 속성이 공유 토큰을 참조할 수 있습니다. 실제 인셋에서 파생된 기하는 `calc()`를 사용할 수 있으며, 추가 스케일 단계가 아닙니다.

일반 둥근 표면은 지원되는 경우 테마의 `superellipse(1.5)` 곡선을 사용합니다. `corner-shape`는 상속되지 않습니다. 테마가 요소와 그 `::before`/`::after`에 적용합니다. 지원하지 않는 엔진은 일반 원형 모서리를 유지합니다. 채움과 그 외곽선이 서로 다르게 휘어지게 만드는 컴포넌트별 스무딩을 도입하지 마세요.

의도된 원과 캡슐을 보존하세요. 아바타와 상태 점은 `50%`를 사용하고, 명시적 알약과 완전 둥근 트랙은 `999px`를 사용할 수 있습니다. 그런 완전 둥근 선언은 모두 같은 규칙에서 `corner-shape: round`와 짝지으세요. 높이가 작다는 이유만으로 모든 버튼을 캡슐로 만들지 마세요. 글리프 표시나 소형 트랙 같은 아주 작은 그리기 디테일은 기존 로컬 기하를 유지할 수 있지만, 주변 컨트롤에 임의의 반경을 정당화하지는 않습니다.

아바타 컨테이너와 그 `img`는 모두 원형으로 유지되어야 합니다. `border-radius`만 상속하는 이미지는 명시적 `corner-shape: round`가 필요하거나 원형 컨테이너에서 곡선을 상속해야 합니다. 둘 다 너비와 높이를 같게 유지하세요. 계정 아바타 크기는 [Account settings](../packages/client/ui-settings-account/README.md#use-this-package)를 참고하세요.

가장자리에 맞닿은 도킹 표면과 인접 셀은 공유 가장자리에서 R0을 사용할 수 있습니다. 카드에 밀착된 헤더, 푸터, 이미지는 노출된 외곽 모서리만 둥글게 하고, 모든 자식을 네 면 모두 둥글게 하지 말고 내부 이음새를 각지게 유지하세요.

<a id="nested-hover"></a>
## 중첩 기하와 hover

자식 반경을 바꾸기 전에 다음 세 배치를 구별하세요:

| 배치 | 규칙 | 예 |
|---|---|---|
| 원형 동심 인셋 | 안쪽 R = max(0, 바깥 R − 인셋); 두 호가 중심을 공유하고 `round` 사용 | 바깥 R16, 인셋 4, 안쪽 R12 |
| 둘러싸는 가장자리에 밀착된 채움 | 둘러싸는 쪽이 보이는 모서리를 소유; 채움을 클리핑하거나 일치하는 모서리를 상속 | 독립적인 hover 영역 두 개가 있는 분할 버튼 카드 |
| 다른 표면 안의 별도 카드 또는 폼 그룹 | 자식의 의미 계층을 선택; 부모 패딩을 기계적으로 빼지 말 것 | R20 설정 카드 안의 R16 편집기 |

표준 메뉴는 바깥 R16, 4px 패딩, R8 항목을 사용하며, 명령 선택, 작업 메뉴, 서브에이전트 및 백그라운드 작업 메뉴의 노출 하이라이트를 포함합니다. 트리 펼침 거터는 들여쓰기를 유지하고, 채워진 작업 행 안의 컨트롤은 자체 컴팩트 기하를 유지합니다. 컴팩트 메뉴는 바깥 R12, 4px 패딩, R8 항목을 사용합니다. 공유 `SegmentedControl`은 바깥 R12, 4px 인셋, R8 세그먼트/표시기를 사용하고, `SegmentedTabs`는 바깥 R16, 4px 인셋, R12 세그먼트/표시기를 사용합니다. 패딩을 바꿀 때 표시기 오프셋, 너비 계산, 서브메뉴 정렬, 포인터 브리지를 일관되게 유지하세요.

반경 빼기는 중첩된 슈퍼타원의 명목 크기 규칙이기도 합니다. 지수가 같아도 정확한 오프셋 곡선이 되지는 않으므로 대각선 간격이 측면 인셋과 다를 수 있습니다. 공유 슈퍼타원 메뉴와 세그먼트 컨트롤 처리를 유지하고, 엄격한 동일 방사 간격이 필요하면 원호를 사용하세요.

하나의 클릭 가능한 표면은 hover를 자기 위에 칠합니다. 밀착된 의사 요소나 오버레이는 보이는 둘러싸는 표면과 같은 반경과 곡선을 사용합니다. 배경과 테두리 사이에 초승달을 남기는 별도로 둥근 채움은 피하세요.

분할 가이드 카드에서는 공유 반경과 클리핑을 바깥 카드에 두고, 밀착된 안쪽 버튼은 각진 모서리를 갖게 하세요. 각 버튼은 자체 hover 색을 유지할 수 있으며 바깥 카드는 두 채움을 하나의 윤곽으로 클리핑합니다. 드롭다운 메뉴는 기존 포털을 통해 클리핑된 하위 트리 밖에 두세요. 외부 포커스 링을 잘라내지 말고 보이는 키보드 포커스 처리를 유지하세요.

```css
.entry {
  border-radius: var(--dsl-guide-entry-radius);
  overflow: hidden;
}

.main,
.trigger {
  border-radius: 0;
}
```

둘러싸는 가이드는 `--dsl-guide-entry-radius: var(--dsw-radius-xl)`을 설정합니다. 바깥 카드가 R20인데 안쪽 버튼에 자체 R28 끝을 주지 마세요.

<a id="settings-cards"></a>
## 설정 카드 재질

계정 프로필, 잔액, 모델 제공자, 프리셋, 플러그인 카드가 이 기본 재질을 공유합니다. 선택, 경고, 오류, 확장 상태는 기하를 유지하면서 기존 의미 색을 사용할 수 있습니다.

```css
.card {
  border-radius: var(--dsw-radius-xl);
  border: 0.5px solid var(--dsw-alias-settings-card-stroke);
  background: var(--dsw-alias-settings-card-fill);
}
```

테마는 팔레트 별칭이 존재하는 `body`에서 카드 채움을 `--dsw-alias-bg-layer-2`로, 테두리를 `--dsw-alias-border-l4`로 해석합니다. 기능 스타일은 두 팔레트 모두에서 이 별칭을 소비합니다. 중첩 편집기는 R16과 기존 모듈 채움을 사용합니다. 계정 사용량/충전 링크는 H36/R12 Button 기하를 따르고, 권한 부여 버튼은 공유 Button을 사용합니다.

평평한 중립 테두리는 공유 0.5px 헤어라인을 사용합니다. 올라온 메뉴, 팝오버, 대화 상자, 패널은 그림자에 헤어라인이 포함된 기존 `--dsw-elevation-*` 재질과 함께 `border: 0`을 사용합니다. 그 테두리 위에 두 번째 중립 테두리를 추가하거나, 탭을 구별하려고 일반 설정 카드에 그림자를 추가하지 마세요. 의미 상태 색 테두리와 기존 반투명 메뉴 배경 동작을 유지하세요.

<a id="verification"></a>
## 적용과 검증

1. 요청된 컴포넌트를 공유 원시 요소, 오버레이, 의사 요소, 형제 변형과 함께 살펴보세요. 값을 바꾸기 전에 역할을 분류하고, 이전 반경의 모든 발생을 같은 새 토큰으로 매핑하지 마세요.
2. 적절한 경우 공유 소유자를 바꾼 뒤 종속 채움, 자식 모서리, 클리핑, 상태 스타일을 정렬하세요. 독립 자식 카드는 자체 계층에 두세요.
3. 밝은 테마와 어두운 테마에서 실제 렌더링된 외곽 크기, 반경, 곡선, 채움, 획을 비교하세요. 해당되는 경우 일반, hover, 눌림/선택, 비활성, 키보드 포커스 상태를 검사하고, 분할 버튼은 양쪽 절반을 hover하세요. 컴포넌트에 영향을 줄 수 있는 좁은 레이아웃과 긴 레이블도 확인하세요.
4. 기존 반경, 모서리 모양, 엘리베이션 스타일시트 가드와 가장 작은 관련 브라우저 시나리오를 사용하세요. 반경 가드는 스케일을 벗어난 리터럴과 알 수 없는 토큰을 거부하지만, 유효한 토큰이 컴포넌트에 적절한지나 두 렌더링 윤곽이 정렬되는지는 판단할 수 없습니다. 그 부분은 시각적으로 확인하세요.
5. 실제 diff에 대해 저장소 검증과 문서화 요구 사항을 따르세요. 의도한 모양을 확인한 뒤에만 영향을 받는 기대치를 갱신하세요. 결과 규칙, 테스트한 표면, 검증하지 못한 상태를 보고하고, 사소한 로컬 조정에 대해 CSS 값만 반복하는 테스트를 추가하지 마세요.
