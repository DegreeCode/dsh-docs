# 포스트모템 0002: 파일시스템 스냅샷 도구가 영구히 비활성화되다

[English](0002-js-expression-disabled-filesystem-tools.md) | [中文](0002-js-expression-disabled-filesystem-tools.zh.md) | 한국어

상태: 해결됨

## 요약

ACP 예제는 `disabled: !!js ...`로 파일시스템 플러그인을 조건부로 활성화하려 했지만, Cordis는 JavaScript 표현식을 플러그인 `config` 안에서만 평가합니다. 원시 표현식 객체가 truthy였으므로 파일시스템 스택은 항상 비활성화되었습니다. 이어서 스냅샷 새로 고침이 `UNKNOWN_TOOL` 결과를 새로운 기대 출력으로 받아들였습니다. 수정은 명시적 파일시스템 오버레이를 사용하고 정적 구성 및 스냅샷 결과 가드를 추가합니다.

## 개요

기본 ACP 구성은 의도적으로 bash 전용입니다. 그 샌드박스가 프로세스 내 파일시스템 제공자를 가둘 수 없기 때문입니다. 파일시스템 스냅샷 시나리오에는 여전히 `read`, `write`, `edit`이 필요하므로 해당 플러그인들을 기본 `cordis.yml`에 넣고, 전체 접근 실행과 스냅샷에서만 활성화하려는 `disabled` 표현식을 붙였습니다.

Cordis Include는 각 `!!js` 스칼라를 표현식 객체로 파싱했습니다. Loader는 플러그인의 `config`는 재귀적으로 보간했지만 `disabled` 같은 엔트리 메타데이터는 그대로 소비했습니다. 따라서 모든 파일시스템 엔트리가 truthy 객체를 보고 모든 모드에서 비활성으로 남았습니다.

## 영향

일곱 개 파일시스템 시나리오와 혼합 워크스페이스 편집 시나리오가 레지스트리에 없는 도구를 호출했습니다. 그 구조화된 세션 로그에는 코드 `UNKNOWN_TOOL`의 `ToolNotFoundError`가 담겼고, stdout은 일반 실패 도구 카드를 렌더링했습니다. 스냅샷 스위트는 두 출력이 새로 고침된 픽스처와 일치했기 때문에 통과했습니다. 즉 성공적인 파일시스템 동작이 아니라 회귀의 결정적 재생을 증명한 것입니다.

실행 중인 격리된 기본 구성은 의도치 않은 파일시스템 접근을 얻지 않았습니다. 순진한 보간 수정은 그 위험을 만들었을 것입니다. 권한 프리셋은 런타임에 bash 샌드박스와 승인 상태를 갱신하지만 파일시스템 스택을 마운트/언마운트하거나 가둘 수는 없습니다.

## 타임라인

- PR #261이 ACP 구성을 통합하고 파일시스템 스냅샷을 새로 고치는 동시에 조건부 파일시스템 엔트리를 도입했습니다.
- 모든 단위, 커버리지, 스냅샷, 문서, 빌드, 위생 검사가 통과했습니다.
- 새로 고침된 파일시스템 기대 출력을 검토하니 일반 실패 카드와 구조화된 `UNKNOWN_TOOL` 결과가 발견되었습니다.
- 실제 Loader 부팅으로 모든 `disabled` 값이 표현식 객체로 남고 모든 파일시스템 fiber가 부재함을 확인했습니다.

## 근본 원인

구현은 `!!js`가 Loader 엔트리 전체에 적용된다고 가정했습니다. 그것은 `entry.options.config`에만 적용됩니다. `Entry._resolveConfig()`가 그 필드를 보간하는 반면 `Entry.disabled`는 보간 없이 `entry.options.disabled`를 검사합니다. YAML 태그는 문법적으로 유효했으므로 로드 시 어떤 진단도 나오지 않았습니다.

스냅샷 프레임워크는 결정적인 트랜스크립트를 유효한 동작으로 취급했습니다. 헤더 pin은 구성된 도구 스키마를 검증했지만, 파일시스템 시나리오는 기본 구성의 pin을 공유했으므로 필요한 도구가 등록되었음을 독립적으로 증명하지 못했습니다. 새로 고침은 의미론적 단언이 누락 도구를 거부하기 전에 기대 stdout과 세션 로그를 다시 썼습니다.

## 추가한 가드레일

- 파일시스템 시나리오는 `fs.cordis.yml`을 부팅합니다. 짝이 되는 재생 구성과 자체 요청 헤더 클래스를 가진 명시적 고정 전체 접근 오버레이입니다.
- [`AGENTS.md`](../../AGENTS.md)와 [Cordis 프라이머](../cordis-primer.ko.md#로더-구성)는 `!!js`가 플러그인 `config`와 엔트리 `disabled`에서 유효하며, 다른 엔트리 메타데이터는 리터럴로 남으므로 조건부 구성은 오버레이를 사용한다고 명시합니다.
- `verify-cordis-config`는 저장소 Cordis YAML을 파싱하고 Loader 엔트리 메타데이터(include 패치와 삽입된 엔트리 포함)의 표현식 노드를 거부합니다.
- `dsh-session-snapshot`은 새 실행과 커밋된 세션 픽스처에서 구조화된 `UNKNOWN_TOOL` 결과를 기대 출력으로 커밋되기 전에 거부합니다.

## 교훈

- 문법적으로 수용된 구성 값이 그 위치에서 평가된다는 보장은 없습니다. 어떤 필드가 보간되는지 문서화하고 검증하세요.
- 스냅샷 새로 고침은 픽스처 생산이지 정확성 검토가 아닙니다. 등록된 도구 누락 같은 의미론적 불가능성에는 기대 출력과 독립적인 단언이 필요합니다.
- 권한 제어는 실제로 관장하는 기능만 설명해야 합니다. 구성 시점의 파일시스템 접근은 런타임 bash 전용 프리셋을 안전하게 따를 수 없습니다.
