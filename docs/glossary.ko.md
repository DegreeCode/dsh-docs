# 용어집

[English](glossary.md) | [中文](glossary.zh.md) | 한국어

DeepSeek Harness의 도메인 용어는 개념마다 하나의 표준 용어를 사용합니다. 각 용어는 표준 Markdown 앵커를 통해 해당 항목으로 연결되며, 구체적인 구현 세부 사항은 각 패키지의 README와 Agent Note에서 다룹니다.

## 기능 seam(capability seam)

- **seam** — 세 가지 역할로 구성된 *교체 가능한 기능 단위*입니다. **Service Definition**(고유한 `ctx.<key>`와 도메인 타입을 소유하는 Cordis `Service`로, `ShellExecutor`와 같은 추상 클래스이거나 `WebRuntime`과 같은 구체 레지스트리이며 TypeScript `interface`는 아닙니다), 하나 이상의 **Service Provider**, 그리고 해당 서비스를 주입받는 하나 이상의 **Consumer**로 이루어집니다. `packages/shell`이 대표적인 예시입니다: `dsh-shell`(Service Definition), `dsh-bash-local` / `dsh-bash-sandbox`(제공자), `dsh-tool-bash`(Consumer). 역할들이 독립적으로 발전해야 할 때는 보통 서로 다른 패키지로 분리하지만, 단일 관심사일 때는 하나의 패키지가 여러 역할을 맡을 수도 있습니다(`dsh-user-approval`은 approval seam의 Service Definition과 구체 구현을 단일 패키지에서 모두 소유합니다). seam은 기능 전체를 의미하며 개별 역할을 뜻하지 않습니다. 이 용어는 반드시 전체 기능 단위를 가리킬 때만 사용하고, 구성 요소는 역할, 클래스, 서비스, 계약, 확장 지점 등의 구체적 명칭으로 불러야 합니다.

## 에이전트 스코프(agent-scope)

- **scope** — 에이전트별 등록 단위입니다. 기여 항목(도구, 프롬프트 섹션, 변수, 제한 규칙, 리스너)은 *전역*(모든 에이전트에 노출)이거나 *스코프 지정*(정확히 하나의 [scope key](#scope-key)에 귀속) 중 하나입니다. 중간 단계 없는 평면적인 2단계 구조입니다. 스코프 지정 등록은 서브에이전트로 상속되지 않으며, 하위 트리의 동작은 스코프 구조가 아닌 [lineage](#lineage) 데이터로 표현합니다.
- **scope key** — 스코프를 식별하는 불투명 식별자(opaque identity)로, 객체 동일성(object identity)으로 비교합니다. 하네스의 기본 규약에 따라 실행 중인 에이전트 인스턴스 자체가 해당 스코프의 키가 됩니다. <a id="scope-key"></a>
- **agent context(`agent.ctx`)** — 에이전트의 스코프 지정 컨텍스트입니다. 이를 통한 등록은 스코프 단위의 가시성과 스코프 수명을 동시에 가지며(단일 사실이 둘을 함께 결정합니다), 여기에 등록된 리스너는 해당 에이전트의 스코프 필터링 디스패치에 참여합니다. 레지스트리 자체를 대상으로 하는 이벤트는 이벤트 계약에 따라 의도적으로 필터링되지 않을 수 있습니다.
- **scope carrier** — 스코프 필터링 디스패치 시 전달되는 `thisArg` 객체입니다(`scopeTarget`이 생성합니다). 이 필터는 태그가 없는 일반 리스너와 해당 대상 자체의 리스너만 허용합니다. 키가 없는 *대상 없는(subject-less)* carrier는 태그가 없는 리스너만 허용합니다.
- **scoped dispatch** — 디스패치 규칙입니다. 특정 에이전트의 활동과 관련된 이벤트는 해당 에이전트의 carrier를 통해 디스패치됩니다. 반면 레지스트리 자체에 관한 이벤트(예: 새 도구 추가)는 *레지스트리 대상*이므로 필터링되지 않고 전역으로 전달됩니다.
- **shadowing** — 가장 구체적인 스코프가 우선하는 이름 해석(name resolution) 규칙입니다. 스코프가 지정된 도구/섹션/변수는 해당 스코프 내에서만 동일한 이름의 전역 항목을 대체합니다. 에이전트별 페르소나 및 에이전트별 도구 변형을 구현하는 메커니즘입니다.
- **restriction / scope-local 등록** — restriction(`tools.restrict`)은 특정 스코프에 대해 전역 도구 집합을 필터링(교집합으로 조합)하며, scope-local 등록은 해당 필터링 이후에 병합됩니다. 필터링으로 제외된 전역 도구는 프롬프트에 나타나지 않을 뿐만 아니라 실행도 거부되어, 애초에 존재하지 않는 도구와 완전히 동일하게 취급됩니다.
- **setup window** — 생성자가 에이전트의 스코프 환경을 구성하는 생성 슬롯(`CreateAgentOptions.setup`)입니다. 스코프와 에이전트 객체는 생성되었지만, 에이전트나 세션이 외부에 공개되기 전, `agent/created` 이벤트가 발생하기 전, 그리고 첫 번째 프롬프트가 조립되기 전의 시점을 의미합니다. setup 단계에서는 등록만 수행하며 에이전트를 직접 구동하지는 않습니다.
- **lineage** — 부모/자식 관계를 나타내는 데이터(`parentSession`, 영속 `delegationDepth`, 런타임 `subagentDepth`)이며, 가시성(visibility)에는 절대 영향을 주지 않습니다. <a id="lineage"></a>

## 목표(goal)

- **목표**(goal) — 기존 세션에 연결되는 영속적인 완료 목표로, 버전 관리되는 `active` / `paused` / `blocked` / `complete` 단계와 goal 라운드 상한을 가집니다. `blocked` 상태에서는 정책 코드와 설명이 보존됩니다. 목표는 상태 데이터일 뿐 스케줄러나 별도의 대화 세션이 아니며, 세션 로그가 단일 신뢰 원천(source of truth)으로 유지됩니다.
- **goal 라운드**(goal round) — 현재 목표를 위해 허용된 하나의 지속 실행 사이클입니다. 동일 세션 드라이버는 goal 라운드를 목표로부터 파생된 하나의 [턴](#turn)으로 구체화하며, 해당 턴은 0개 이상의 단계를 포함할 수 있습니다. 동일 세션에서 발생하는 목표와 무관한 일반 사용자 턴은 goal 라운드 상한을 소모하지 않습니다. <a id="goal-round"></a>
- **goal 활성화**(goal activation) — 연속 실행 소비자가 다음 goal 라운드를 실행할 수 있도록 허용하는 프로세스 로컬 권한입니다. 활성화 상태는 `armed` 또는 `disarmed` 중 하나입니다. 이 상태는 영속 재생 기록에 의도적으로 포함되지 않으므로, 세션 재개나 포크 후 자동 작업을 다시 시작하려면 `/goal` 명령이나 모델 도구를 통한 사용자의 명시적인 재개 승인이 필요합니다.

## 사용자 명령(human command)

- **사용자 명령**(human command) — 슬래시(`/`)로 시작하는 지시어로, 사용자 대상 어댑터가 `ctx.commands`를 통해 해석하고 실행하며 모델 메시지로 전달되지 않습니다. 모델용 도구나 `ctx.shell`을 통한 셸 명령 실행과는 명확히 구분됩니다.
- **명령 평면**(command plane) — UI 어댑터와 명령 플러그인이 담당하는 발견, 파싱, 디스패치, 취소, 결과 렌더링 영역입니다. 핸들러가 별도로 영속 도메인 데이터를 수정하지 않는 한 명령의 출력은 순수한 UI 상태로 남습니다.
- **goal 명령**(goal command) — `dsh-command-goal` 패키지가 제공하는 `/goal` 사용자 명령입니다. 현재 목표를 직접 확인하거나 수정하며, 영속적이고 모델에 노출되는 모든 기록은 goal 도메인이 직접 관리합니다.

## 루프 계층(loop hierarchy)

- **턴**(turn) — 세션에서 접수된 입력을 한 차례 완전히 처리(소진)하는 단위로, 모델과 도구 실행이 멈추거나 종료 정책이 개입할 때 끝납니다. <a id="turn"></a>
- **단계**(step) — 하나의 모델 요청과 그 응답으로 인해 실행되는 도구 호출들의 묶음입니다. 하나의 턴은 0개 이상의 단계를 포함합니다. <a id="step"></a>
- **라운드**(round) — 턴을 감싸는 외부 정책의 반복 단위로, [goal 라운드](#goal-round)나 새로운 에이전트를 사용하는 Ralph 시도 등이 해당합니다. 라운드 카운터는 해당 정책에 귀속되며 세션 내의 모든 턴을 무조건 세지는 않습니다. <a id="round"></a>
- **교환**(exchange) — 첫 [단계](#step)에서 사용자 입력을 수락한 턴부터 다음 사용자 입력을 수락하는 턴 직전까지 이어지는 일련의 연속된 [턴](#turn)들의 묶음입니다. 완료된 서브에이전트, goal 라운드, 예약 알림 등으로 깨어난 턴들은 앞선 교환에 포함됩니다. 채팅 UI의 '다음 메시지 접기' 기능은 최신 교환을 펼친 상태로 유지합니다. <a id="exchange"></a>

## Ralph

- **Ralph 루프**(Ralph loop) — 변경 불가능한 단일 목표를 달성하기 위해 새로운 에이전트를 전경에서 순차 실행하는 워크플로입니다. 워크플로 및 서브에이전트 기본 요소를 조합하여 구성한 모델 대상 도구 정책이며, 동일 세션의 goal, 에이전트 루프 모드, 스케줄러, 또는 범용 워크플로 스크립트 기능과는 다릅니다. <a id="ralph-loop"></a>
- **Ralph 라운드**(Ralph round) — [Ralph 루프](#ralph-loop)에서 실행되는 새로운 개별 자식 세션입니다. 자식 세션은 부모 세션이나 이전 자식 세션의 대화 시드를 물려받지 않으며, 공유 워크스페이스와 경계가 명확한 단일 [Ralph 핸드오프](#ralph-handoff)를 통해 라운드 간 상태를 전달합니다. <a id="ralph-round"></a>
- **Ralph 핸드오프**(Ralph handoff) — 진행 중인 Ralph 라운드에서 다음 라운드로 전달되는 정규화되고 구조화된 보고서로, 상태, 요약, 증거 자료, 다음 단계, 차단 요인 등을 포함합니다. 공유 워크스페이스를 대체하는 것이 아니라 보완하는 역할을 합니다. <a id="ralph-handoff"></a>
