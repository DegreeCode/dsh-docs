# 번역 규칙

[English](translation-rules.md) | [中文](translation-rules.zh.md) | 한국어

이 저장소의 문서 쌍 양쪽 사이에서 번역하는 방법입니다. 두 언어는 동등한 권위를 가집니다([README.md](README.ko.md)). 변경은 어느 언어로든 작성되며 작성한 쪽이 그 갱신의 원본입니다. 이 규칙들은 대응 문서를 만들거나 갱신하는 일을 규율합니다. 규칙은 사람과 에이전트를 똑같이 구속합니다. 일상적인 에이전트 작업은 용어집을 참고한 한 번의 패스로 변경된 내용을 직접 번역하며, 확장 [.agents/skills/dsh-translate-docs](../../.agents/skills/dsh-translate-docs/SKILL.md) 워크플로는 사용자가 명시적으로 호출할 때만 실행합니다. 규칙 수준은 RFC 2119 관례를 따릅니다. **MUST** / **MUST NOT**은 게이트나 리뷰를 막고, **SHOULD**는 벗어나려면 이유를 밝혀야 하며, **MAY**는 재량입니다.

## 충실성

- 대응 문서는 *MUST* 원본 쪽이 말하는 바를 말해야 합니다. 동작, 사전 조건, 경고, 버전 주장, 예시를 더하거나 빼지 않습니다. 쌍이 실질 내용에서 어긋나면 어느 언어도 기본적으로 이기지 않습니다. 틀린 쪽을 고친 뒤 같은 변경에서 다른 쪽도 맞춥니다.
- 대응 문서는 *SHOULD* 단어 대 단어 주석이 아니라 해당 언어의 자연스러운 기술 문장으로 읽혀야 합니다. 의미를 번역하고, 대상 문법이 원하는 곳에서 문장을 재구성하며, 작성자의 문체를 유지합니다. 간결한 문장은 간결하게 남깁니다.
- 번역할 수 없는 것은 번역하지 않습니다. 문장이 원어의 관용 표현에 기대고 있어 자연스러운 옮김을 거부한다면, 관용 표현이 아니라 그 생각을 번역하세요.

## 문체

- 문체는 [style-samples.md](style-samples.md)로 보정합니다. 문서 장르마다 하나씩 있는, 사람이 승인한 모범 쌍입니다. 대응 문서는 가장 가까운 샘플의 대상 언어 쪽과 일치해야 합니다(MUST). 샘플의 문체와 본문 문체 규칙이 어긋나면 샘플이 우선합니다. 중국어 번역은 격식 있는 기술 중국어를, 영어 문서는 간결하고 전문적인 개발자 기술 문체를 사용합니다.
- 번역가가 문장을 자리바꿈하는 것이 아니라, 그 언어의 기술 저자가 내용을 다시 진술하듯 쓰되 원문의 모든 절을 보존하세요. 더하지도 빼지도 않으며, 유창함이 절을 잃는 이유가 될 수 없습니다.
- 대상 언어에서 행위자가 흐려질 수 있으면 문장에 행위자를 명시하세요. 중국어에서는 모호한 수동태나 추상적 주어를 실제 행위자(系统、门禁、评审人)로 바꿉니다.
- 직역보다 대상 언어의 확립된 엔지니어링 관용 표현을 선호하세요(예: false positive/negative → 误报／漏检, enforcement frontier → 执行红线). 은유는 이식하지 말고 현지화하며, 대상 언어가 요구하면 명사 연쇄를 풀어 쓰세요.
- 긴 문단은 의미 단위로 나눕니다. 문단마다 하나의 생각입니다. 문단 경계는 원문과 달라도 되며(MAY), 구조 시그니처는 문단을 세지 않습니다.
- 중국어로 번역할 때 범주 명사는 첫 등장에 영어 주석을 붙인 중국어를 씁니다(实操手册（cookbook）). 영어로 번역할 때는 관례적인 영어 범주 이름을 씁니다. 디렉터리나 파일을 그대로 가리키는 참조는 코드 형식의 영어로 둡니다.

## 구조 보존

쌍 게이트는 제목 깊이, 펜스 코드 블록, 표의 행·열 수, 목록 종류, 순서 목록 시작 번호, 목록 항목 수, 링크 로케일, 의미상 대상을 검사합니다. 나머지 틀은 직접 보존하며, 쌍을 이루는 파일은 다음 항목에서 1:1로 일치해야 합니다(MUST):

- 제목 계층(같은 수준, 같은 순서 — 제목 TEXT는 번역합니다),
- 목록 형태와 번호,
- 표(같은 열, 같은 행 순서, 헤더 셀은 용어집에 따라 번역),
- 펜스 코드 블록 — **주석을 포함해 바이트 단위로 동일**; 쌍 시그니처가 정보 문자열과 내용을 비교하며, ` ```ts ` 블록은 `doc-typecheck`에서 컴파일됩니다,
- 인라인 코드 스팬(명령, 플래그, 구성 키, 파일 경로, 이벤트 이름, API 이름, 버전 번호) — 그대로 두며 번역하거나 서식을 바꾸지 않습니다,
- 링크와 앵커: 모든 상대 문서 링크는 같은 의미상 대상과 정확한 쿼리/프래그먼트 접미사를 유지해야 합니다(MUST). 대상이 활성 이중 언어 코퍼스에 속하면 영어 쪽은 `.md` 경로를, 중국어 쪽은 `.zh.md` 경로를 씁니다. 그 코퍼스에 대응 문서가 없으면 오류이며, 코퍼스 밖 대상은 원래 경로를 유지합니다. 외부 URL, 이미지, 순수 페이지 내 프래그먼트는 그대로 둡니다. 언어 전환 줄은 명시적인 로케일 간 예외로 남고, GitHub 밖에서 렌더링되는 README는 [README.md](README.ko.md)에 문서화된 대로 정확한 대응 문서를 가리키는 표준 공개 저장소 URL을 써도 됩니다(MAY). 링크 TEXT는 번역합니다.

저장소의 Markdown 관례는 `.zh.md` 파일에도 그대로 적용됩니다. 문단마다 하나의 물리적 줄(`verify-md-wrap`), 상대 링크 해석(`verify-md-links`), 정확히 하나의 끝 개행입니다.

## 용어

- [terminology.md](terminology.md)는 양방향의 진실 공급원입니다. 번역 전에 이를 읽어 들이세요. 나열된 모든 용어는 자신의 행과 그 "不要译作" 금지를 따라야 합니다(MUST). 중국어 대상은 "中文" 열과 그 "首次出现" 주석을 쓰고, 영어 대상은 중국어 주석을 덧붙이지 않고 "English" 열을 씁니다.
- 중국어 대상에서 목록에 없는 기술 용어는 주요 중국어 OSS나 벤더 문서(K8s/Vue/MDN 중국어 문서, 微软简中风格指南, 대형 기술 기업 프로젝트 문서)의 확립된 표기를 PR에 인용하여 쓸 수 있습니다(MAY). 그런 선례가 없으면 영어로 두고 제안 표기와 함께 「待定术语」(보류 용어)에 올려야 합니다(MUST).
- 영어 대상에서는 확립된 영어 기술 용어를 씁니다. 원어 용어에 명확한 확립된 대응어가 없으면 짧은 설명 주석과 함께 원어를 보존하고 보류 용어에 올리세요. 어느 방향도 즉석에서 표기를 만들어 낼 수 없으며, 결정된 용어는 같은 PR이나 후속 PR에서 [terminology.md](terminology.md)에 들어갑니다.

## 추가 언어

쌍은 선택적인 한국어 번역본 `foo.ko.md`를 함께 둘 수 있습니다(MAY). [README.md](README.ko.md#쌍-계약)를 참고하세요. 한국어는 공식 이중 언어(en/zh) 페어링 계약 외부에 위치합니다. 영어가 항상 원본 기준이며, `.i18n.yaml` 레코드는 한국어 문서를 추적하지 않고 쌍 게이트도 이를 건너뜁니다. 한국어 문서는 이 지침의 내용 충실성, 문서 구조, 기술 용어, 번역 품질 규칙을 준수하며 `[English](foo.md) | [中文](foo.zh.md) | 한국어`로 시작합니다. 상대 문서 링크는 대응하는 `.ko.md` 파일이 존재하면 해당 파일을 가리키고, 없으면 영어 원문을 가리킵니다. 한국어 본문 서술은 정중한 `합니다` 체를 사용합니다. 코드 블록, 인라인 코드, 명령어, 식별자는 영어 원문과 바이트 단위까지 동일하게 유지하며, 한국어 기술 용어는 임의의 직역이 아니라 업계에서 확립된 표준 기술 용어를 따릅니다.

## 타이포그래피

이 규칙들은 중국어 쪽을 규율합니다. 영어 쪽은 저장소의 일반 Markdown 관례(루트 `AGENTS.md`)를 따릅니다. 아래의 혼용 문자 규칙은 [MDN 중국어 번역 가이드](https://github.com/mdn/translated-content/blob/main/docs/zh-cn/translation-guide.md), [Kubernetes zh-cn 현지화 가이드](https://kubernetes.io/zh-cn/docs/contribute/localization_zh/), [Vue.js 중국어 번역 규칙](https://github.com/vuejs-translations/docs-zh-cn/wiki/%E7%BF%BB%E8%AF%91%E9%A1%BB%E7%9F%A5), [中文文案排版指北](https://github.com/sparanoid/chinese-copywriting-guidelines)의 프로젝트 간 합의를 따르며, 이들은 다시 [W3C clreq](https://www.w3.org/TR/clreq/)와 GB/T 15834—2011에 근거합니다:

- 중국어 텍스트와 라틴 단어 사이, 중국어 텍스트와 숫자 사이에는 반각 공백을 하나 넣어야 합니다(MUST). 예: `每个 plugin 注册 3 个 tool`。전각 문장부호와 다른 무엇 사이에는 공백을 넣지 않습니다.
- 중국어 산문에서는 전각(중국어) 문장부호를 써야 합니다(MUST). 예: `，。：；？！（）「」`. 반각 문장부호는 코드 스팬 안, 그대로 인용한 완전한 영어 문장 안, 숫자(`3.5`, `1,024`) 안에만 남습니다.
- 중국어 산문은 *SHOULD* 줄표(em dash)보다 콜론, 마침표, 쉼표, 괄호를 선호합니다. 다른 문장부호로 문장을 자연스럽게 보존할 수 없을 때만 줄표를 남깁니다.
- 열거 쉼표: 중국어에서 병렬 항목 목록은 쉼표가 아니라 가운뎃점(顿号, 、)을 씁니다.
- 전각 숫자나 전각 라틴 문자를 써서는 안 됩니다(MUST NOT). `１２３`은 절대 안 되고 `123`을 씁니다.
- 고유 명사는 표준 대소문자를 유지합니다. GitHub, TypeScript, DeepSeek처럼 쓰며, 코드를 인용하는 경우가 아니면 `github`나 `Github`로 쓰지 않습니다.
- 2인칭은 您이 아니라 你입니다(Vue와 Kubernetes 중국어 관례, 이 저장소의 직접적인 문체와 일치).
- 강조 표시(`**bold**`, `*italic*`)는 원문과 같은 스팬에 유지합니다. 중국어에는 이탤릭이 없으므로 렌더링된 강조가 같아 보일 수 있지만, 인용 부호나 다른 장식으로 대체하지 않습니다.

## 품질 기준

- 이중 언어 엔지니어가 어느 파일만 읽어도 다른 쪽 독자가 얻는 모든 것(같은 사실, 같은 주의 사항, 같은 어조)을 얻고 그 이상은 얻지 못할 때 쌍이 완성됩니다.
- 기록, 전환 줄, 제목 깊이, 코드 블록, 표의 행·열 수, 목록 종류, 순서 목록 시작 번호, 목록 항목 수, 링크, 저장소 Markdown 규칙은 `pnpm run verify-translation-pairing`과 나머지 `doc-sync`를 실행해 확인합니다. 목록과 표의 순서, 비표준 목록 번호, 인라인 코드, 강조, 의미, 용어, 어조는 사람 리뷰가 담당합니다.

## 참고 자료

이 규칙이 인용하는 권위 문서로, 배경 근거를 확인하려는 사람과 에이전트를 위한 것입니다:

- [中文文案排版指北](https://github.com/sparanoid/chinese-copywriting-guidelines) — 한자·라틴 문자 혼용에서의 띄어쓰기와 문장부호에 대한 사실상의 커뮤니티 표준입니다.
- [MDN zh-CN 번역 가이드](https://github.com/mdn/translated-content/blob/main/docs/zh-cn/translation-guide.md) — 이 문서와 같은 형태의 저장소 내 번역 규칙 파일이며, 띄어쓰기, 문장부호, 용어 관행을 다룹니다.
- [Kubernetes zh-cn 현지화 가이드](https://kubernetes.io/zh-cn/docs/contribute/localization_zh/) — 가장 큰 중국어 현지화 팀의 용어 첫 등장 표기와 문장부호 관행입니다.
- [Vue.js docs-zh-cn 翻译须知](https://github.com/vuejs-translations/docs-zh-cn/wiki/%E7%BF%BB%E8%AF%91%E9%A1%BB%E7%9F%A5) — 용어별 번역·유지 결정과 어조를 다룹니다.
- [zh-style-guide](https://zh-style-guide.readthedocs.io) — 이 문서가 규칙 수준 분류(와 RFC 2119 키워드 수준)를 빌려온 커뮤니티 중국어 기술 작성 스타일 가이드이며, GB/T 15834/15835, clreq, 벤더 가이드를 종합합니다.
- [W3C clreq](https://www.w3.org/TR/clreq/)와 [Microsoft 중국어 간체 스타일 가이드](https://learn.microsoft.com/en-us/globalization/reference/microsoft-style-guides) — 형식적 타이포그래피와 벤더 현지화의 기준선입니다.
- GB/T 19682-2005《翻译服务译文质量要求》 — 이 문서의 충실성과 용어 절이 실행 규칙으로 구체화한 세 가지 기본 요구 사항(忠实原文, 术语统一, 行文通顺)을 담은 국가 표준입니다.
