# 리마인더 예약

[English](schedule.md) | [中文](schedule.zh.md) | 한국어

## 요약

대화에서 리마인더를 만들고, 자동화 작업 페이지에서 활성·비활성 작업을 확인하며 활성 작업의 이름, 지시문, 실행 시각을 편집합니다. 매일 반복 리마인더는 저장된 현지 시각과 시간대를 따르고, 고정 간격 리마인더는 경과 간격을 따릅니다. 전달된 일회성 작업은 직접 삭제할 때까지 남아 있습니다.

## 리마인더 만들기

기본 제공 웹 프로필에는 호스트 예약 서비스와 자동화 작업 페이지가 포함되어 있습니다. 리마인더 생성을 요청하기 전에 모델 제공자를 구성하세요.

`standard`, `cordis`, `ptc` 프리셋은 네 가지 리마인더 도구와 모델에 현재 시각과 브라우저의 시간대를 알려 주는 시계 컨텍스트를 선언하므로, 이 프리셋들은 `schedule_create`, `schedule_list`, `schedule_update`, `schedule_delete`를 제공합니다. `minimal` 프리셋은 둘 다 선언하지 않습니다. 위임된 서브에이전트는 프리셋의 위임 행이 이 네 도구를 거부하므로 네 도구 중 어느 것도 볼 수 없으며, 그럼에도 호출이 도달하면 거부됩니다.

모델에 리마인더 생성, 목록, 편집, 삭제를 요청합니다. 모델은 `schedule_create`, `schedule_list`, `schedule_update`, `schedule_delete`를 사용하며, 업데이트는 리마인더 하나를 제자리에서 변경하고 id와 저장된 전달 기록을 유지합니다. 반면 자동화 작업 페이지의 새 자동화 작업은 요청이 입력창에 이미 작성된 상태로 새 세션을 열어 생성합니다. 지원되는 선택지는 양의 정수 초 단위 일회성 지연, 절대 날짜와 시각, 최소 1분의 고정 간격, IANA 시간대를 포함한 매일 현지 시각, IANA 시간대와 월요일 1부터 일요일 7까지의 ISO 요일에 기반한 매주 현지 시각, 명시적 IANA 시간대를 포함한 5필드 cron 표현식이며, 모두 정규 형식으로 저장됩니다.

예를 들어 “매일 23:00(Asia/Shanghai)에 날씨를 확인하라고 알려 줘.”라고 요청합니다. 자동화 작업을 열고 생성된 리마인더를 선택합니다. 주기에 1회가 아니라 매일 규칙과 요청한 시간대가 표시되는지 확인합니다. 일회성 리마인더는 전달된 후 반복으로 바뀌지 않습니다.

## 작업 확인 및 삭제

사이드바에서 자동화 작업을 열면 대화를 활성화하지 않고도 세션 전반의 리마인더를 볼 수 있습니다. 저장된 작업 이름, 지시문, 작업의 내부 세션 id로 검색하고, 전체·사용·비활성 중 하나의 상태 행으로 필터링합니다. 활성 작업이 하나 이상 있는 세션의 유휴 상태이고 보관되지 않은 행에는 시계 표시가 나타나며, 보관된 행에서는 해당 셀이 비어 있고 실시간 상태는 호버 카드에만 표시됩니다. 활성 작업이 있는 세션 행을 길게 호버하면 해당 작업 중 최대 두 개가 주기 및 다음 실행 시각과 함께 나열되며, 다음 실행 시각은 기기 시간대 기준 시각과 상대 기간으로 표시됩니다. 활성 리마인더가 있는 동안 열린 세션의 헤더에는 아이콘 형태의 리마인더 시계가 표시되며, 작업이 하나뿐이면 그 작업의 상세 정보를 열고, 그렇지 않으면 세션 리마인더 목록을 엽니다.

작업을 선택해 규칙을 연 다음 기록을 선택하면 저장된 최신 기록 20건을 불러옵니다. 저장된 각 기록은 시계 글리프, 작업에 저장된 시간대(일회성 또는 간격 작업은 브라우저 시간대) 기준의 발생 시각, 지시문이 저장되어 있으면 그 지시문으로 이루어진 간결한 한 행으로 표시됩니다. 저장된 지시문이 없는 기록은 현재 지시문을 대신 표시하지 않습니다. 이전 기록 더 불러오기는 다음 페이지를 추가합니다. 기록은 시계가 뒤로 가더라도 최신순 저장 순서를 따르며 모델 실행 결과를 나타내지 않습니다. 원본 세션 항목은 상세 탭 스트립에 있어 규칙 보기를 스크롤하는 동안에도 계속 보입니다. 보조 키가 없는 좌/우 화살표와 Home/End는 포커스된 탭을 전환하며, Alt, Ctrl, Meta, Shift 조합은 가로채지 않습니다. 작업을 새로 고쳐도 선택한 탭은 유지됩니다.

기록 보기가 비어 있다는 것은 쿼리가 성공했지만 저장된 기록이 없다는 뜻입니다. 로딩 중, 요청 실패, 작업 없음, 유효하지 않은 이전 기록 커서에는 각각 다른 메시지가 표시됩니다. 요청이 실패했거나 작업 없음 응답을 받으면 전달 기록 다시 시도를 사용하고, 커서가 유효하지 않으면 전달 기록 새로 고침으로 최신 페이지를 다시 불러옵니다. 요청이 실패하는 동안 이전에 불러온 기록이 경고와 함께 계속 표시될 수 있습니다. 새 전달이 발생하면 최신 페이지가 갱신됩니다. 떠난 작업이나 보기에 대한 늦은 응답은 현재 보기를 대체하지 않습니다.

저장된 이력이 없는 작업은 새 전달이 기록을 추가할 때까지 기존 최신 영수증만 표시할 수 있으며, 이후 전달이 누락된 이력을 복구하거나 그 안내를 지우지는 않습니다. 저장되지 않은 이전 기록과 지시문 스냅샷은 복구할 수 없고, 저장된 지시문이 없을 때 현재 지시문으로 대체하지 않습니다. 이전 이력 안내는 호스트가 이전 기록을 사용할 수 없다고 표시할 때만 나타나며, 전달이 없는 새 작업은 그 안내 없이 빈 상태를 표시합니다.

활성 작업만 예약에 참여합니다. 비활성 작업은 추가 전달을 예약하지 않습니다. 일회성 작업은 리마인더가 대화 인박스에 영구적으로 기록된 후 비활성 상태가 되며, 전체 또는 비활성 필터를 선택해 찾을 수 있습니다. 대화 헤더 카탈로그와 모델의 `schedule_list`는 활성 리마인더만 표시하므로, 해당 보기에서 사라졌다고 해서 유지된 작업이 삭제된 것은 아닙니다.

상세 탭 스트립의 연결된 세션 항목은 메타데이터가 준비되었고 세션을 사용할 수 있으며 보관되지 않은 경우 원본 대화를 엽니다. 그렇지 않으면 이유와 함께 항목이 비활성화됩니다. 원본 세션을 열 수 없더라도 작업 상세 정보와 삭제 동작은 계속 사용할 수 있습니다. 작업을 탐색해도 세션의 보관이 해제되지는 않습니다.

작업 삭제를 선택하고 확인하면 향후 전달이 중지되고 목록에서 작업이 제거됩니다. 비활성 작업도 마찬가지입니다. 삭제하면 작업과 저장된 전달 기록이 함께 제거되므로 작업의 저장된 이력이 사라집니다. 삭제를 확인하면 요청한 패널이나 탭이 닫히고 앱 전체 공지 하나로 결과를 알립니다. 결과는 삭제됨이거나, 작업을 유지한 채 다시 시도할 수 있는 실패입니다. 원본 대화를 제거하거나 이미 대기 중인 메시지를 철회하지는 않습니다. 성공한 쿼리가 남은 작업을 확인할 때까지 행은 계속 표시됩니다. 쿼리가 실패하면 다시 시도로 카탈로그를 다시 불러오며, 이 오류는 빈 성공 결과가 아닙니다.

## 활성 작업 편집

자동화 작업에서 활성 작업을 선택하고 규칙을 열어 이름, 지시문, 실행 시각을 편집합니다. 비활성 작업은 읽기 전용이며, 변경 사항 저장을 선택할 때까지 편집 내용은 로컬 초안에 남습니다. 편집해도 작업 id, 원본 대화, 최신 전달 영수증, 저장된 모든 전달 기록은 유지됩니다.

- 매일 및 매주: 시간과 시간대를 편집하며, 매주 규칙은 요일도 전환합니다. 시계 행은 정수 초를 표시하고, 건드리지 않은 행은 제출 시 저장된 밀리초 값을 유지하며, 저장된 IANA 시간대도 유지됩니다. 변경된 규칙은 아래 서머타임 규칙에 따라 첫 번째 미래 발생 시점을 선택합니다.
- N시간마다, N분마다, N초마다 중 하나를 선택하고 행에 표시된 단위로 수량을 입력합니다. 해당 단위에서 허용되는 최소 간격은 1시간, 1분, 60초이며, 제출되는 간격은 정수 초입니다. 간격을 변경하면 호스트가 저장을 승인한 시각부터 새 간격이 시작되고 첫 대상은 한 간격 뒤가 됩니다. 시간대는 이 경과 간격에 영향을 주지 않습니다.
- 일회성 After/At: 날짜, 시간, 시간대를 각각 편집합니다. 초기 시간대는 기록에 저장된 시간대(기록에 없으면 이 기기의 시간대)이고, 초기 시계 값은 같은 저장 시점을 가리킵니다. 시간대를 저장하지 않은 일회성 규칙에는 선택한 시간대가 입력한 날짜와 시간을 해석한다는 안내가 하나 표시됩니다. 시간대를 바꾸면 시계 값은 유지되고 시점이 바뀝니다. 대상을 변경하면 같은 작업 id로 At으로 저장됩니다. 시간대는 반복 메타데이터로 유지되지 않습니다.

이 행들은 로컬 초안만 변경합니다. 변경 사항 저장은 이름, 지시문, 전체 규칙을 한 번의 업데이트로 제출하며, 초안이 저장된 작업과 다르면 저장 표시줄이 나타납니다. 취소는 저장된 값을 복원합니다. 반복 메뉴에는 매주, 월요일~금요일, 매일, N시간마다, N분마다, N초마다, 1회, 사용자 지정(cron)이 있으며 호스트는 어느 것이든 받아들이므로 일회성 After가 At으로 저장될 수 있습니다. 동일하게 정규화되는 규칙은 쓰기나 대상 재설정을 일으키지 않습니다. 같은 간격 규칙은 타이밍을 다시 시작하지 않고, 변경되지 않은 일회성 대상은 After 또는 At을 유지합니다. 저장이 진행되는 동안 행은 비활성화됩니다. 카드를 벗어나도 이미 시작된 호스트 쓰기는 롤백되지 않습니다.

카탈로그를 새로 고치면 편집한 필드는 유지하고 나머지 필드는 갱신된 기록에서 가져오므로, 저장하지 않은 편집이 있어도 다른 필드에 대한 동시 변경은 살아남습니다. 유효하지 않은 입력은 보고되고 저장을 막습니다. 전달이나 다른 편집이 작업을 변경했다면 충돌이 발생해 그 변경을 덮어쓰지 못하므로, 최신 규칙을 편집하려면 다시 시도하세요. 승인된 업데이트는 카탈로그를 갱신합니다. 거부되었거나 확인되지 않은 업데이트는 카탈로그 로딩 오류와 다릅니다. 카탈로그를 다시 불러오려면 다시 시도를 사용하고, 승인된 업데이트를 반복하는 용도로 쓰지 마세요. 업데이트 자체를 확인할 수 없으면 다시 시도하기 전에 작업을 확인하세요. 상세 정보를 닫거나 작업을 전환한 뒤 도착한 늦은 응답은 현재 보기를 대체하지 않습니다.

## 시각과 전달 참조

리마인더는 세션이 열려 있지 않아도 저장된 상태로 유지됩니다. 호스트가 실행 중일 때 리마인더의 실행 시각이 도래하면 원본 세션을 복원하고 현재 진행 중인 작업을 방해하지 않으면서 후속 작업을 큐에 넣습니다. 호스트를 재시작하면 저장된 작업을 확인하여, 기한이 지난 일회성 작업이나 반복 작업에 대해 놓친 최신 발생 건 1회만 전송합니다. 호스트 프로세스를 종료하면 다시 시작할 때까지 예약 처리가 중단됩니다. 동일한 세션에서 동시에 만료된 여러 반복 작업은 하나의 메시지로 묶여 전달될 수 있습니다.

고정 간격 리마인더는 간격이 바뀌기 전까지 생성 시점에 맞춰 유지되며, 간격을 바꾸면 저장 승인 시각에 맞춰집니다. 반면 매일 리마인더는 저장된 현지 시각과 IANA 시간대를 따릅니다. 존재하지 않는 현지 시각이나 날짜는 건너뛰고, 겹치는 시각은 그날 한 번만 이른 시점을 사용합니다. 절대 시각 요청은 존재하지 않는 현지 시각을 거부하고 겹치는 경우 이른 시점을 선택합니다. 브라우저는 자연어 요청을 해석할 때 자신의 시간대를 제공하며, 시간대를 명시하면 모호함을 피할 수 있습니다. 작업 상세 정보는 저장된 벽시계 규칙의 시간대를 주기 텍스트에 유지하고 모든 다음 대상을 기기 시간대 기준 시계로 표시합니다. 일회성 작업은 UTC 시점만 저장하므로 타임스탬프에 브라우저 시간대를 사용합니다.

저장된 전달 기록은 메시지가 대화 인박스에 영구 기록되었음을 확인하는 것이지, 모델이 요청된 작업을 완료했음을 뜻하지 않습니다. 인박스 영속화나 작업 쓰기가 실패하면 저장 기록이 추가되지 않습니다. 인박스 영속화 이후 크래시나 작업 쓰기 실패가 발생하면 전달된 메시지가 기록되지 않은 채 전달이 반복될 수 있으며, 정확히 한 번 전달은 보장되지 않습니다. 이 기록은 실행 이력이나 외부 알림 채널이 아닙니다.

저장된 기록은 승인이 추가될 때 정리됩니다. 호스트는 승인 시각이 추가된 영수증의 `deliveredAt`에서 거꾸로 계산한 구성된 `deliveryHistoryDays` 기간에 들어오는 기록을 유지하며, 최대 최신 `deliveryHistoryRecords` 건까지만 보관합니다. 최신 영수증은 항상 남고, 정리된 구간은 이전 기록을 사용할 수 없는 상태로 표시합니다. 호스트는 보관된 이력을 메모리에 두고 승인이 있을 때마다 작업 행 전체를 다시 씁니다. 페이지네이션은 반환되는 기록 수만 제한하며 보관된 이력이나 지시문 바이트는 제한하지 않습니다.

일시 중지와 실행마다 새 세션을 만드는 것은 지원되지 않습니다. 이름, 지시문, 실행 시각 편집은 모델의 경우 `schedule_update`로 가능하며, 이는 리마인더를 제자리에서 변경하고 id와 저장된 전달 기록을 유지합니다. 자동화 작업 페이지에서는 선택한 작업의 바인딩에 대해 편집할 수 있습니다. 어느 쪽도 세션 간 릴레이 워크플로가 아닙니다. 이전 세션 로그에만 기록된 리마인더는 자동으로 예약되지 않으므로 필요한 것은 다시 만드세요. 이전에 삭제된 작업 기록은 재구성되지 않습니다.
