# 리버스 프록시 뒤에서 웹 UI 게시하기

[English](public-deployments.md) | [中文](public-deployments.zh.md) | 한국어

`dsh --profile web`은 웹 GUI를 루프백(loopback) 포트에서 서비스하므로 기본적으로 외부 머신의 브라우저에서는 접근할 수 없으며, 프로세스 자체는 외부에서 실제로 접속하는 공개 주소를 알지 못합니다. 공개 호스트 이름, TLS 암호화, 백엔드 리스너로 전달하기 전의 경로 접두사 제거 등은 앞단의 리버스 프록시가 담당합니다. 이때 `--public-url`을 사용하면 DSH 프로세스에 브라우저가 접속하는 외부 공개 주소를 전달할 수 있습니다:

```sh
dsh --profile web --public-url https://app.example/ui/ --trusted-host app.example
```

## `--public-url`의 역할

`--public-url`은 마운트 접두사(선택 사항)가 포함된 `http://` 또는 `https://` 루트 URL을 받아 `/`로 끝나도록 정규화합니다. 이 값은 콘솔에 출력되거나 자동으로 브라우저에서 열리는 시작 URL, `DSH_WEB_URL` 환경 변수, 그리고 에이전트 런타임 컨텍스트의 웹 GUI URL을 구성합니다. 내부 웹 서버는 계속 루트(`/`) 기준으로 라우트를 처리하며 프록시의 마운트 경로를 직접 알지 못합니다. 설정 파일의 `publicUrl` 필드도 동일한 역할을 합니다.

## 프록시가 해야 할 일

- **브라우저가 전송한 원래의 `Host` 헤더 보존.** 보안 펜스(fence)는 수신한 `Host`를 허용된 호스트 목록과 비교하므로, 프록시는 `Host` 헤더를 로컬 리스너 주소로 재작성(rewrite)하지 않고 그대로 백엔드에 전달해야 합니다.
- **마운트 접두사 제거(Path Stripping).** 내부 리스너는 루트 경로 라우트에 응답하므로, 프록시는 `/ui/api/...` 요청의 접두사를 제거하여 `/api/...` 형태로 백엔드에 전달해야 합니다.
- **프로토콜 업그레이드 전달.** 브라우저 요청과 WebSocket 업그레이드는 `Upgrade` 및 `Connection` 헤더를 그대로 유지한 채 리스너에 도달해야 합니다. 프록시가 HTTPS를 제공할 경우 TLS는 프록시의 외부 구간에서 종료됩니다.
- **쿠키 `Path` 범위 재작성.** 평문 HTTP로 서비스하는 백엔드는 `Secure` 플래그 없이 host-only `Path=/` 쿠키를 발급하며, 프록시는 쿠키의 `Path`를 마운트 경로(`/ui/`)로 재작성한 뒤 HTTPS 구간에서 `Secure` 플래그를 추가합니다. 리스너 자체가 TLS를 직접 제공하는 경우 쿠키에 이미 `Secure`가 붙으므로 프록시는 `Path`만 재작성하면 됩니다.
- **마운트 경로 리디렉션.** `/ui/`가 유일한 진입점입니다. 이 경로를 통해서만 최초 시작 토큰(token)이 세션 쿠키로 교환되며, 이미 쿠키를 보유한 브라우저에는 `/ui/` 또는 `/ui/index.html`이 문서를 제공합니다. 웹 문서는 자체 디렉터리를 기준으로 상대 URL을 해석하므로, `/ui` 요청은 반드시 끝에 슬래시가 붙은 `/ui/`로 리디렉션되어야 하며, 접두사가 제거된 백엔드는 외부 원래 경로를 스스로 복원할 수 없습니다.

## 브라우저가 사용하는 authority 신뢰하기

펜스는 루프백(loopback), 리스너 자신의 바인드 주소, 그리고 `--trusted-host`가 지정한 모든 호스트를 허용합니다. 브라우저가 다른 호스트 이름으로 배포에 접근하면 프록시 설정이 아무리 올바르더라도 모든 API 호출이 403 거부를 받으므로, 브라우저에 표시되는 호스트를 반드시 `--trusted-host`로 지정하세요. `--public-url`은 단순히 주소 표시용일 뿐 접근을 허용하는 권한 목록에는 포함되지 않습니다. 포트 번호가 없는 호스트 항목은 모든 포트와 일치하므로 동적 포트로 바인딩하는 터널에 적합합니다. 펜스는 네트워크 레벨의 요청 진입을 허용할 뿐이며, 실제 사용자 인증은 콘솔에 출력되는 URL의 시작 토큰과 서명된 세션 쿠키가 담당합니다. 이는 TLS가 어디서 종료되든 동일하게 적용됩니다. 서버 인증서는 서버의 신원을 브라우저에 증명할 뿐, 브라우저 사용자의 신원을 인증하지는 않습니다.

알리는 URL도 펜스도 리스닝 포트 자체를 보호하지 않으므로, 포트를 신뢰하는 프록시나 네트워크로 제한하세요.

## 외부 구간 보호하기

TLS는 프록시에서, 리스너 자체에서, 또는 양쪽에서 종료할 수 있으며 `--public-url`은 여전히 알림일 뿐입니다. 브라우저를 향하는 `http://` 루트는 시작 token을 평문으로 노출합니다. `https://` 프록시 루트는 브라우저와 프록시 사이 구간을 보호하며, 프록시와 리스너 사이의 암호화 여부는 리스너의 TLS 구성에 따릅니다.

리스너에서 종료하려면 `--tls-cert`와 `--tls-key`를 전달합니다. 각각 프로세스 작업 디렉터리를 기준으로 해석되는 경로이며, 인증서 파일에는 전체 체인을, 키 파일에는 암호가 없는 PEM 개인 키를 담습니다. DSH는 인증서를 획득, 갱신, 감시하지 않으며 캐리어(carrier, 실행 프로세스)가 파일을 한 번만 읽으므로, 바꾸려면 파일을 교체한 뒤 리스너를 다시 로드하거나 프로세스를 다시 시작해야 합니다. 파일이 없거나 유효하지 않으면 시작이 실패하며 HTTP로 대체되지 않습니다. 브라우저는 자체 신뢰 저장소와 이름 검사를 적용하므로 인증서가 접속하는 hostname 또는 IP를 포함해야 합니다. 기본 포트는 3080으로 유지됩니다. 네이티브 TLS에는 프록시가 필요 없지만, 프록시 배포와 `--public-url`은 각각 독립적으로 계속 지원됩니다. TLS 리스너는 세션 cookie에 `Secure`를 표시하므로, 브라우저가 해당 cookie를 돌려보낼 수 있도록 공개 브라우저 구간은 HTTPS로 유지하세요.

출력되는 URL에는 프로세스 자격 증명이 포함되므로 의도한 사용자에게만 공유하세요.

[웹 앱 참조](../../../packages/bundle/web-app/README.md#public-deployments)에서 `--public-url`, `--trusted-host`, `--tls-cert`/`--tls-key` 명령줄 옵션을 설명합니다. 웹 프로필에서 `publicUrl`은 `web-runtime` 행을, `trustedHosts`는 [Connection 행](../../../packages/client/connection/README.md)을, `tls`는 [webserver 행](../../../docs/subsystems/web-server.ko.md#구성)을 구성합니다.
